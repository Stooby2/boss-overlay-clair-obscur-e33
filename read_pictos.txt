Goal

Add picto tracking to `boss-overlay` by reusing the save JSON that `boss-overlay` already produces with `uesave.exe`, then matching the picto IDs found in the save against a picto catalog that can be built from `boss-overlay/originalGameMapping`.

Everything in this document refers only to files inside `boss-overlay`.

Files that matter

- Save conversion and parsing:
  - `boss-overlay/electron/saveParser.ts`
- File watching and refresh flow:
  - `boss-overlay/electron/saveWatcher.ts`
  - `boss-overlay/electron/main.ts`
  - `boss-overlay/electron/preload.ts`
- Renderer types and app state:
  - `boss-overlay/src/vite-env.d.ts`
  - `boss-overlay/src/App.tsx`
  - `boss-overlay/src/types/Boss.ts`
- Packaging:
  - `boss-overlay/electron-builder.json`
- Picto source data:
  - `boss-overlay/originalGameMapping/createcustommappings.py`
  - `boss-overlay/originalGameMapping/DT_jRPG_Items_Composite.json`
  - `boss-overlay/originalGameMapping/DT_PictosDefinitions.json`

What to read from the save

The authoritative save paths for pictos are:

1. Found:
   - `root.properties.InventoryItems_0.Map`
2. Mastered:
   - `root.properties.PassiveEffectsProgressions_0.Array.Struct.value`
3. Level:
   - `root.properties.WeaponProgressions_0.Array.Struct.value`

Use these exact field names when typing the JSON:

- Inventory item ID:
  - `key.Name`
- Inventory count:
  - `value.Int`
- Passive effect picto ID:
  - `Struct.PassiveEffectName_3_A92DB6CC4549450728A867A714ADF6C5_0.Name`
- Mastery flag:
  - `Struct.IsLearnt_9_2561000E49D90653437DE9A45BE2A86D_0.Bool`
- Weapon progression picto ID:
  - `Struct.DefinitionID_3_60EB24664894755B19F4EBA18A21AF1A_0.Name`
- Picto level:
  - `Struct.CurrentLevel_6_227A00644D035BDD595B2D86C8455B71_0.Int`

How to build the picto catalog

Best option: generate a static JSON file once and load it at runtime.

Add:

- `boss-overlay/data/pictos.json`

Recommended shape:

```json
{
  "Pictos": {
    "APDiscount": "AP Discount",
    "AcceleratorHeal": "Accelerating Heal"
  }
}
```

How to derive that mapping from files already in `boss-overlay`

`boss-overlay/originalGameMapping/createcustommappings.py` already contains the exact logic in `genpictomapping()`:

1. Read `boss-overlay/originalGameMapping/DT_jRPG_Items_Composite.json`
2. Iterate its `Rows`
3. Keep only rows where:
   - `Item_Type_88_2F24F8FB4235429B4DE1399DBA533C78 == 'E_jRPG_ItemType::NewEnumerator10'`
4. Use the row key as the internal picto ID
5. Use `Item_DisplayName_89_41C0C54E4A55598869C84CA3B5B5DECA.SourceString` as the friendly name
6. If `SourceString` is missing, fall back to `CultureInvariantString`
7. The script also marks some unavailable entries with `*` or `**`

Important:

- The row key is the thing that appears in the save.
- Do not join on friendly names.
- Friendly names are just display labels.

If you do not want to run the Python script, implement the same logic directly in TypeScript and write out `data/pictos.json`.

Recommended runtime model

Add a new type:

```ts
export interface Picto {
  id: string
  friendlyName: string
  found: boolean
  mastered: boolean
  level: number
}

export interface SaveSnapshot {
  bosses: Boss[]
  pictos: Picto[]
}
```

Recommended file changes

1. `boss-overlay/src/types/Picto.ts`
   - Add `Picto`
   - Add `SaveSnapshot` or put `SaveSnapshot` in another shared type file

2. `boss-overlay/data/pictos.json`
   - Add the generated picto catalog

3. `boss-overlay/electron/saveParser.ts`
   - Extend `SaveData` to include the three pictos-related save structures
   - Add a picto catalog loader similar to `loadBossDatabase()`
   - Add `extractPictos(saveData): Picto[]`
   - Change `parseSaveFile(savePath)` to return `SaveSnapshot` instead of just `Boss[]`
   - Change the cache to store the full snapshot

4. `boss-overlay/electron/saveWatcher.ts`
   - Expect `parseSaveFile()` to return a snapshot
   - Keep newly-killed detection based on `snapshot.bosses`
   - Callback should become `callback(snapshot, newlyKilled?)`

5. `boss-overlay/electron/main.ts`
   - Send the snapshot over the existing IPC event
   - You can keep the event name `boss-update` to minimize churn
   - The payload should become `{ bosses, pictos }`

6. `boss-overlay/electron/preload.ts`
   - Update `onBossUpdate` typing to use the snapshot payload

7. `boss-overlay/src/vite-env.d.ts`
   - Update `electronAPI` types to match the new payload

8. `boss-overlay/src/App.tsx`
   - Add picto state
   - In the save update listener:
     - `setBosses(snapshot.bosses)`
     - `setPictos(snapshot.pictos)`

9. UI
   - Add a renderer component such as `boss-overlay/src/components/PictosChecklist.tsx`
   - Keep v1 read-only
   - The request is tracking, not editing

Recommended extraction logic

Inside `extractPictos(saveData)`:

1. Build `inventoryDict` from `InventoryItems_0.Map`
   - key: `el.key.Name.toLowerCase()`
   - value: `el.value.Int`

2. Build `masteryDict` from `PassiveEffectsProgressions_0.Array.Struct.value`
   - key: `el.Struct.PassiveEffectName_3_A92DB6CC4549450728A867A714ADF6C5_0.Name.toLowerCase()`
   - value: `el.Struct.IsLearnt_9_2561000E49D90653437DE9A45BE2A86D_0.Bool`

3. Build `levelDict` from `WeaponProgressions_0.Array.Struct.value`
   - key: `el.Struct.DefinitionID_3_60EB24664894755B19F4EBA18A21AF1A_0.Name.toLowerCase()`
   - value: `el.Struct.CurrentLevel_6_227A00644D035BDD595B2D86C8455B71_0.Int`

4. Iterate every known picto from `data/pictos.json`

5. Emit:
   - `id`
   - `friendlyName`
   - `found: (inventoryCount ?? 0) > 0`
   - `mastered: masteryDict.get(idLower) ?? false`
   - `level: levelDict.get(idLower) ?? 1`

Behavior to preserve

- Found comes from inventory membership
- Mastered comes from passive effect progression
- Level comes from weapon progression
- Default level is `1`
- Matching should be case-insensitive

Minimal `SaveData` additions

Add these optional properties under `root.properties` in `boss-overlay/electron/saveParser.ts`:

```ts
InventoryItems_0?: {
  Map: Array<{
    key: { Name: string }
    value: { Int: number }
  }>
}

PassiveEffectsProgressions_0?: {
  Array: {
    Struct: {
      value: Array<{
        Struct: {
          PassiveEffectName_3_A92DB6CC4549450728A867A714ADF6C5_0: {
            Name: string
          }
          IsLearnt_9_2561000E49D90653437DE9A45BE2A86D_0: {
            Bool: boolean
          }
        }
      }>
    }
  }
}

WeaponProgressions_0?: {
  Array: {
    Struct: {
      value: Array<{
        Struct: {
          DefinitionID_3_60EB24664894755B19F4EBA18A21AF1A_0: {
            Name: string
          }
          CurrentLevel_6_227A00644D035BDD595B2D86C8455B71_0: {
            Int: number
          }
        }
      }>
    }
  }
}
```

Packaging note

If you add `boss-overlay/data/pictos.json`, packaging should already include it because `boss-overlay/electron-builder.json` already copies the whole `data` directory in `extraResources`.

Use the same path pattern already used for `bossDatabase.json`:

- dev: `../data/pictos.json`
- prod: `process.resourcesPath + /data/pictos.json`

UI recommendation for v1

Add a simple read-only checklist that shows:

1. total found / total known
2. search
3. optional filters:
   - all
   - found
   - missing
   - mastered
4. per-row fields:
   - friendly name
   - found
   - mastered
   - level

What not to do

- Do not run `uesave.exe` a second time just for pictos
- Do not join on friendly names
- Do not infer found from mastery or level
- Do not build this as a manual override system first

Suggested order of work

1. Add `data/pictos.json`
2. Extend `electron/saveParser.ts`
3. Return a full snapshot from `parseSaveFile()`
4. Flow snapshot through `saveWatcher.ts`, `main.ts`, `preload.ts`, `vite-env.d.ts`
5. Update `App.tsx`
6. Add `PictosChecklist.tsx`

Validation checklist

1. Boss tracking still works unchanged
2. Pictos render even when none are found
3. A known-found picto becomes found after a save update
4. A mastered picto only shows mastered when `IsLearnt` is true
5. Missing weapon progression falls back to level 1
6. Packaged app still finds both `data/bossDatabase.json` and `data/pictos.json`

Exact place to start

Start in `boss-overlay/electron/saveParser.ts`.

That file already performs the expensive part: converting `.sav` to JSON with `uesave.exe`. Extend it so one parse produces both:

- `bosses`
- `pictos`
